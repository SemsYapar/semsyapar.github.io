CryptUnprotectData — call flow

The reverse of protect: app → crypt32 → dpapi.dll → ALPC → lsass/dpapisrv → back. The blob goes in as ciphertext; lsass decrypts it with the master key named inside the blob, then the plaintext is transit-encrypted for the trip back. Names in green have their own diagram.

flags used above
PROMPT_ON_UNPROTECT 0x1 / PROMPT_ON_PROTECT 0x2 / PROMPT_STRONG 0x8 — pPromptStruct bits; STRONG adds ent2 LOCAL_MACHINE 0x4 — the blob is sealed under the machine master key (any local user can unprotect) VERIFY_PROTECTION 0x40 — advise (via 0x91012) if the blob's alg is weaker than host policy; still decrypts AUDIT 0x10 — emit the security audit event SYSTEM 0x20000000 — reserved; an ordinary caller setting it gets 0x57 (used only by internal, in-process calls)
