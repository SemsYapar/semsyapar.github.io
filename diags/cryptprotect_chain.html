CryptProtectData — call flow

How a plaintext becomes a persistent DPAPI blob: app → crypt32 → dpapi.dll → ALPC → lsass/dpapisrv → back. The real encryption happens in lsass with the master key; on the wire the plaintext is protected by a separate transit layer. Names in green have their own diagram.

PROMPT_ON_PROTECT 0x2 / PROMPT_ON_UNPROTECT 0x1 / PROMPT_STRONG 0x8 — pPromptStruct bits; STRONG adds ent2 LOCAL_MACHINE 0x4 — seal under the machine master key, any local user can later unprotect CRED_SYNC 0x8 — master-key sync, not a data op CRED_REGENERATE 0x80 — regenerate the DPAPI credential AUDIT 0x10 — emit the security audit event SYSTEM 0x20000000 — reserved; an ordinary caller setting it gets 0x57 (used only by internal, in-process calls)
