GetMasterKey — acquiring the 64-byte master key

The GetPreferredMasterKey / GetSpecifiedMasterKey step of the protect and unprotect diagrams, expanded. Inside lsass/dpapisrv: from the account's credential to the master key that actually (de)crypts data. Runs only on a cache miss.
called by SPCryptProtect / SPCryptUnprotect
GetPreferredMasterKey (protect → the active key) · GetSpecifiedMasterKey(GUID from the blob) (unprotect) both converge on GetMasterKey; only where the GUID comes from differs

pre-key (DP_KEK) — the credential that unlocks the file
user pre_key = HMAC-SHA1(SHA1(password), SID) [CPSGetDerivedCredential] SYSTEM / service pre_key = DPAPI_SYSTEM half, used as-is [CPSGetSystemCredential] fixed virtual acct pre_key = HMAC-SHA1(DPAPI_SYSTEM half, account name)
The password hash comes from lsass — the plaintext never arrives. No-password accounts use a 20-byte half of the DPAPI_SYSTEM LSA secret (machine half for LOCAL_MACHINE, user half otherwise); only the fixed virtual accounts (kinds 0x5a/0x5b/0x63) add an HMAC over the account name. The pre-key feeds the KDF below, it is not applied to the master key directly.
↓
GetMasterKey — read the file, try credentials in order (first success wins)
ReadMasterKey → split MASTERKEY_STORED into: MasterKey · BackupKey · CredHist · DomainKey try DecryptMasterKeyFromStorage with each credential until the MAC matches:   1. the caller's current credential (ComputeMasterKeyUserEncryptionKey)   2. other identities for the account (GetMasterKeyUserEncryptionKey, alternate SIDs)   3. old passwords from the CredHist chain (after a password change) if none match → RestoreMasterKey: decrypt BackupKey with the domain/local backup key (RSA) if that also fails → master key not recovered
↓ DecryptMasterKeyFromStorage → DecryptMasterKeyToMemoryEx
DecryptMasterKeyToMemoryEx — the actual unseal
① PKCS5DerivePBKDF2(pre_key, salt, rounds) → key ‖ iv (XOR-feedback variant, not textbook PBKDF2) ② AES-CBC decrypt(key, iv) → hmacSalt ‖ hmac ‖ masterKey(64) ③ verify HMAC → match: the 64-byte master key · mismatch: wrong/old credential → caller tries the next one
↓
cache + return
InsertMasterKeyCache(LUID + GUID) → later calls skip the file path return the 64-byte master key → SPCryptProtect / SPCryptUnprotect
